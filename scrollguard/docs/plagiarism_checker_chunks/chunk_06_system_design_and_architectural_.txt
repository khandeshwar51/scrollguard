8.3. Database Design (Continued: Daily Aggregate & Escalation State)

Synchronous Cache Layer Design: While raw session and video event telemetry is persisted asynchronously in IndexedDB, the daily aggregate totals and escalation state flags are cached in chrome.storage.local , which provides fully synchronous read access via the chrome.storage.onChanged event listener. This ensures that the React widget receives instantaneous state updates without awaiting IndexedDB promise chains during high-velocity swiping.

Table 8.3: Data Dictionary - DAILY_AGGREGATE & ESCALATION_STATE (chrome.storage.local)

Midnight Rollover Architecture: The background service worker monitors the system clock via chrome.alarms.create({ periodInMinutes: 1 }) . On each alarm tick, it evaluates new Date().toISOString().slice(0, 10) against the stored date field. Upon detecting a calendar day transition (midnight rollover), the worker atomically: (1) archives the current DAILY_AGGREGATE to IndexedDB as a historical record; (2) initializes a fresh aggregate with all counters set to zero; (3) resets all ESCALATION_STATE flags to their initial values; and (4) resets the in-memory session tracker.

Write Atomicity Guarantee: Both chrome.storage.local.set() operations -- updating the daily aggregate and resetting escalation state -- are batched into a single storage transaction object, ensuring they either both commit or both fail. This prevents partial-write race conditions where the aggregate might be reset while the escalation state retains stale override thresholds from the previous day.
