Design Pattern Analysis - Observer Pattern: VideoTracker implements the Observer design pattern by registering an IntersectionObserver instance that passively monitors HTMLVideoElement objects entering the viewport threshold. Upon receiving a viewport intersection callback, VideoTracker notifies WidgetController (the Subject) to update its internal clip counter state. This decoupling ensures that the tracking logic remains independent of the UI rendering lifecycle.

Design Pattern Analysis - State Pattern: WidgetController implements the State design pattern via the focusState discriminated union field, which transitions through states: -> -> -> -> . Each state maps to a distinct rendered component tree within the Shadow DOM, ensuring that the UI always reflects the current behavioral intervention tier without complex conditional rendering logic scattered across components.

Separation of Concerns: BehaviorClassifier , DopamineEngine , and ScrollSpeedEngine are stateless pure-function modules with no side effects. This architectural constraint ensures they are fully testable in isolation via Vitest unit tests without requiring browser environment mocking.

This accurately reflects the progressive, non-mandatory escalation architecture of the friction ladder.

8.3. Database Design & Relational Data Schema

Hybrid Client-Side Persistence Architecture: ScrollGuard implements a two-tier, fully client-side persistence model that intentionally avoids any cloud server dependency. High-frequency, append-only video event telemetry is stored in the browser

Table 8.1: Data Dictionary - VIDEO_EVENT Entity (Primary IndexedDB Object Store)

Table 8.1 Description: The VIDEO_EVENT store captures atomic, indivisible records representing a single continuous video playback window. Each record is keyed by videoId (surrogate platform identifier) combined with startTime (epoch milliseconds) to form a naturally unique composite primary key, since the same video may be rewatched within a single session.

BCNF Normalization Analysis: All non-key attributes in VIDEO_EVENT -- specifically watchDurationMs , completed , skipped , and platform -- are in full functional dependency on the composite primary key (videoId, startTime) . No partial key dependencies or transitive functional dependencies exist within this entity, confirming that the schema satisfies Third Normal Form (3NF) and Boyce-Codd Normal Form (BCNF).

Indexing Strategy: A secondary B-tree index is automatically maintained on the startTime field to support efficient time-range queries. The web analytics dashboard queries VIDEO_EVENT filtered by a 7-day or 30-day time range using IDBKeyRange.bound(startEpoch, endEpoch) , returning results in under 10 milliseconds on standard consumer hardware.
